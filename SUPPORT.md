# Support

Thank you for your interest in Plutus.

This document explains how to get help, report issues, and engage with the project
in a manner that maintains efficient and sustainable support.

---

## Getting Help

Plutus is an open source project maintained by volunteers.

If you need help:

1. **Check the documentation**
   - README.md
   - SECURITY.md (for security-related concerns)

2. **Search existing issues**
   - Your question or problem may already be discussed or resolved.

3. **Open a GitHub Issue**
   - Use this for:
     - Bug reports
     - Feature requests
     - Clarification on expected behavior
     - Documentation improvements

Please include:
- Clear description of the problem
- Steps to reproduce (if applicable)
- Expected vs actual behavior
- Environment details (OS, Python version, Docker version)

---

## What This Project Does Not Provide

The maintainers do **not** provide:

- Guaranteed response times
- Production support or SLAs
- Private debugging or system design consulting
- Support for heavily customized forks

If you need commercial-grade support, you are expected to arrange it independently.

---

## Security Issues

**Do not open public issues for security vulnerabilities.**

Please follow the instructions in [`SECURITY.md`](SECURITY.md) to report security concerns responsibly.

---

## Feature Requests

Feature requests are welcome, but please note:

- Plutus is intentionally opinionated and minimal
- Features must align with the project’s core goals:
  - Correctness
  - Idempotency
  - Scalability
  - Observability
- Large or breaking changes should be discussed in an issue before submitting a PR

---

## Contributions vs Support

If you can fix a bug or improve documentation yourself, contributions are
strongly encouraged. Please see `CONTRIBUTING.md` for guidelines.

---

## Community Expectations

All interactions are governed by the project’s
[`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).

Be respectful, concise, and professional.

---

## A Note on Responsiveness

Maintainers may not respond immediately.
Lack of response does not imply lack of interest — it usually reflects limited time.

Constructive, well-documented issues are far more likely to receive attention.
